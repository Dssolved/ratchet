## План

Реализовывать строго по порядку, не перескакивая.

### Шаг 0 — каркас · ✅ готово

- Vite 8 + React 19 + TS 7 + Tailwind v4, версии из [../CLAUDE.md](../CLAUDE.md#стек)
- Zustand store + persist в IndexedDB (`idb-keyval`), хук `useHydrated`
- Типы в `src/domain/types.ts`, конвейер миграций в `src/store/migrations.ts`
- Работа с локальными датами и ISO-неделями — `src/domain/dates.ts`
- Seed из [progressions.md](progressions.md): 6 семейств, шаблоны A/B/Свободная
- Экспорт и импорт JSON с проверкой формата и снимком перед заменой
- `npm run check` (typecheck + oxlint) и `npm run build` проходят чисто

Что проверено вручную в браузере:

- seed рендерится, стартовые ступени и диапазоны совпадают с документом
- persist пишет в IndexedDB только данные, экшены не утекают
- подменённое хранилище подхватывается при перезагрузке (гидратация работает)
- сброс к seed создаёт снимок перед перезаписью
- импорт: валидный файл применяется; не-JSON, чужой JSON, будущая версия схемы и бэкап
  без движений дают понятные ошибки и **не разрушают текущие данные**

Правки модели, всплывшие при реализации: `unit` переехал на ступень (Д-14), версия схемы
вынесена в обёртку (Д-15).

## Открытые вопросы

- Точные требования Capacitor 8 к JDK и Android SDK — уточнить на шаге 2 при первой сборке
  и записать в [android.md](android.md).
- Диапазоны и стартовые ступени в [progressions.md](progressions.md) — гипотеза. Проверяются
  первыми тренировками, правятся из вкладки «Настройки». Особенно ступень 5 брусьев:
  падение с 3×15 до 3×7–8 ожидаемо, но величину шага увидим на практике.
