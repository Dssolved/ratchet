# Android: окружение, сборка, отладка

Проект платформы уже создан и лежит в `android/` — его создал `npx cap add android`,
для этого SDK не нужен. Всё, что ниже, требуется только чтобы **собрать APK**.

## Разделение инструментов

| Инструмент | Роль |
|---|---|
| **WebStorm** | весь код, дев-сервер, отладка. Здесь проходит ~95% работы |
| **Android Studio** | нужна не как IDE, а как способ поставить Android SDK и JDK |

Android Studio построена на IntelliJ, интерфейс будет знакомым. После первичной настройки
открывается редко: сборку можно запускать из терминала WebStorm.

## Требования (проверено 2026-08-15)

Из документации Capacitor и сгенерированного `android/variables.gradle`:

| Что | Версия | Откуда |
|---|---|---|
| Node.js | 22+ | требование Capacitor 8 (стоит 24.18) |
| Android Studio | 2025.2.1 или новее | минимум для Capacitor 8 |
| Android SDK Platform | **API 36** (Android 16) | `compileSdkVersion`/`targetSdkVersion` |
| Минимальная версия Android на телефоне | API 24 (Android 7.0) | `minSdkVersion` |
| Gradle | 8.14.3 | скачается сам через wrapper |
| Android Gradle Plugin | 8.13.0 | зафиксирован в `android/build.gradle` |

### JDK: нужен именно 21, не тот, что принесла Android Studio

Документация Capacitor обещает, что отдельный JDK не нужен. **На этой машине это неверно**,
и вот почему:

- Android Studio принесла **JBR 25**;
- Capacitor сгенерировал **Gradle 8.14.3**, а он поддерживает Java максимум **24**
  (по официальной матрице совместимости Gradle, Java 25 умеет только Gradle 9.1+);
- сборка падает с `Unsupported class file major version 69` — 69 это Java 25.

Поэтому поставлен **Eclipse Temurin JDK 21**:

```
winget install --id EclipseAdoptium.Temurin.21.JDK --source winget
```

Путь: `C:\Program Files\Eclipse Adoptium\jdk-21.0.12.8-hotspot`

Альтернативой было поднять Gradle до 9.x, но тогда AGP 8.13 оказался бы на Gradle 9,
на который официально не рассчитан — менять два звена сборки сразу ради обхода не стоит.

Системная Java 8 роли не играет, трогать её не надо. Но **`gradlew` берёт JVM из `JAVA_HOME`
или из `PATH`**, а там как раз Java 8, поэтому при сборке из терминала `JAVA_HOME` надо
задавать явно — см. ниже. Если собирать через Android Studio, там свой параметр:
**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**, его тоже
надо переключить на 21.

## Основной цикл разработки — без Android вообще

```bash
npm run dev -- --host
```

Vite напечатает адрес вида `http://192.168.x.x:5173` — заходить с телефона по домашнему
Wi-Fi. Изменения прилетают мгновенно, сборка APK не нужна.

Этого достаточно для всего, кроме локальных уведомлений при потушенном экране.

**Если с телефона не открывается:** сеть помечена как Public, в этом профиле Windows режет
входящие. Лечится один раз, из PowerShell от администратора:

```
Set-NetConnectionProfile -Name "ИМЯ_СЕТИ" -NetworkCategory Private
New-NetFirewallRule -DisplayName "Vite dev 5173" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow -Profile Private
```

## Разовая настройка

1. Скачать и установить **Android Studio** (2025.2.1+) с developer.android.com/studio.
   Мастер первого запуска поставит SDK и JDK сам.
2. В **SDK Manager** (Settings → Languages & Frameworks → Android SDK) убедиться, что стоят:
   - **Android SDK Platform 36**
   - **Android SDK Build-Tools**
   - **Android SDK Platform-Tools** (в них `adb`)
3. Переменные окружения: `ANDROID_HOME` на папку SDK (обычно
   `C:\Users\<имя>\AppData\Local\Android\Sdk`), в `PATH` добавить `%ANDROID_HOME%\platform-tools`.
4. На телефоне: **Настройки → О телефоне**, семь тапов по «Номер сборки», затем
   **Для разработчиков → Отладка по USB**.
5. Подключить телефон кабелем, разрешить отладку в диалоге, проверить: `adb devices`
   должен показать устройство.

## Сборка APK

```bash
npm run android:sync
```

Собирает веб-часть и переносит её в android-проект. Дальше из терминала — **обязательно
с явным `JAVA_HOME`**, иначе `gradlew` возьмёт из `PATH` системную Java 8 и упадёт:

```
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.12.8-hotspot"
cd android
.\gradlew.bat assembleDebug
```

APK окажется в `android/app/build/outputs/apk/debug/app-debug.apk`. Установка:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Либо `npm run android:open` — откроется Android Studio, дальше кнопка Run. Так удобнее,
когда что-то сломалось в Gradle и нужны его подробные сообщения.

**Первая сборка идёт долго** — на этой машине заняла 11.5 минут: Gradle скачивает себя,
зависимости AndroidX, а также недостающие компоненты SDK. Последующие сборки — секунды.

Кстати, **SDK Platform 36 и Build-Tools 35 Gradle доставил сам**: лицензия уже была принята
мастером Android Studio, и AGP докачал недостающее. Ставить их руками через SDK Manager
не потребовалось.

## Проверка уведомлений

Ради этого приложение и собирается в APK. После установки: **Настройки → Уведомления →
«Проверить уведомление»**, разрешить уведомления, заблокировать экран и убрать телефон
в карман. Через 15 секунд должно прийти уведомление.

Если не приходит — смотреть в сторону энергосбережения: многие прошивки (Xiaomi, Huawei,
Samsung) по умолчанию душат фоновую активность. Приложению нужно снять ограничения
батареи в системных настройках.

Разрешения (`POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`, `WAKE_LOCK`,
`RECEIVE_BOOT_COMPLETED`) объявляет сам плагин и они вливаются в манифест при сборке —
править `AndroidManifest.xml` руками не нужно.

## Отладка внутри APK

Capacitor — это обычный WebView, поэтому доступен полноценный DevTools:

1. Телефон подключён по USB, приложение открыто.
2. В Chrome на компьютере — `chrome://inspect`.
3. Найти устройство, нажать `inspect`.

Дальше консоль, сеть, элементы, брейкпоинты — всё как в вебе. Android Studio для отладки
фронтенда не нужна.

## appId менять нельзя

`io.github.dssolved.ratchet`, задан в `capacitor.config.ts`. Android считает приложение
с другим appId **другим приложением**: старое придётся удалить, а вместе с ним уйдёт
IndexedDB, то есть весь журнал тренировок. Менять — только до первой установки.

## Что коммитим

Папку `android/` — **да**: там манифест, иконки, конфиг. Capacitor кладёт туда свой
`.gitignore`, который исключает `build/`, `.gradle/`, `local.properties`, скопированные
веб-ассеты и сгенерированные конфиги. Ничего добавлять не нужно.

`local.properties` содержит абсолютный путь к SDK, у каждой машины свой — поэтому
не коммитится.

## Релизная сборка

Понадобится, только если захочется собрать подписанный APK начисто. Требует создания
keystore. **Keystore и пароли в репозиторий не кладутся никогда.** Для личного
использования достаточно debug-сборки.

## Иконка и экран запуска

Исходники — `assets/`. Правится SVG, всё остальное генерируется.

| Файл | Роль |
|---|---|
| `icon.svg` | цельная иконка: старые лаунчеры, PWA, веб |
| `icon-foreground.svg` / `.png` | передний слой адаптивной иконки — знак, прозрачный фон |
| `icon-background.svg` / `.png` | фоновый слой — сплошная заливка |
| `splash.svg`, `splash-dark.svg` | экран запуска |

Перегенерация:

```
npx capacitor-assets generate --android
```

### Две ловушки генератора, из-за которых иконка ломается молча

**1. Слои адаптивной иконки он берёт только из PNG.** Если положить только
`icon-foreground.svg`, генератор его молча проигнорирует и вставит в передний слой
непрозрачную картинку из `icon.svg`. Адаптивная иконка перестанет быть двухслойной,
и при обрезке маской внутри круга проступит квадрат.

PNG растрируются из тех же SVG:

```
node -e "const s=require('sharp'),f=require('fs');for(const n of ['icon-foreground','icon-background'])s(f.readFileSync(`assets/${n}.svg`),{density:384}).resize(1024,1024).png().toFile(`assets/${n}.png`)"
```

**2. Отступ 16.7% он ставит на оба слоя, включая фоновый.** Фон обязан заливать слой
целиком — он для того и нужен, чтобы маска любой формы попала в цвет. С отступом
лаймовый квадрат ужимается, и **углы квадратной маски оказываются пустыми**.

Правится вручную в `mipmap-anydpi-v26/ic_launcher.xml` и `ic_launcher_round.xml`:
у `<background>` отступа быть не должно, у `<foreground>` — должен. **После каждой
перегенерации правку надо повторять**, файлы перезаписываются. В самих файлах на этот
счёт оставлен комментарий.

### Как проверять

Только на телефоне и только на домашнем экране. Ни один из этих двух дефектов
не виден ни в браузере, ни в макете: они проявляются исключительно при обрезке
реальной маской лаунчера.

Знак должен читаться на 48 пикселях — это размер иконки в самых плотных списках.
Геометрия и обоснования — в [design.md](design.md#знак).
