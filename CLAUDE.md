# Ratchet

Оффлайн-трекер тренировок по калистенике для одного пользователя. Название — от храпового
механизма: прогресс фиксируется по ступеням и не откатывается.

**Язык проекта — русский.** Документация, комментарии, UI, тексты коммитов — по-русски.
Код (идентификаторы, имена файлов) — по-английски.

## Стек

**Бэкенда нет.** Все данные живут на устройстве. Бэкап — экспорт/импорт JSON.

## Команды

```bash
npm run dev              # дев-сервер
npm run dev -- --host    # дев-сервер с доступом по локальной сети (проверка с телефона)
npm run build            # прод-сборка в dist/
npm run typecheck        # tsc --noEmit
npm run check            # typecheck + oxlint
npm run android:sync     # собрать и перенести в android-проект
```

Разработка идёт в WebStorm. Android Studio нужна только ради Android SDK — см.
[docs/android.md](docs/android.md).

## Главный принцип

**Хранятся только факты и решения. Всё остальное вычисляется.**

Факты — записанные подходы. Решения — переходы по ступеням. Рекорды, стрики, готовность
к усложнению, суммарные повторения, ачивки — **производные**, считаются на лету из журнала
и никогда не хранятся в состоянии. Это позволяет добавлять новые метрики и получать их
сразу по всей накопленной истории.

Если возникает соблазн закешировать производную величину в state — сначала перечитать
[docs/decisions.md](docs/decisions.md).

## Правила работы

- В начале сессии читать `docs/progress.md`, в конце — обновлять его.
- **Проверки делятся так: браузерные — на агенте, телесные — на пользователе.**
  Тайпчек, линтер и поведение гоняются в браузере — это дёшево и ловит настоящие баги.
  Вибрацию, уведомления, ощущение тач-таргетов, безопасные зоны и всё, что зависит
  от маски лаунчера, проверяет пользователь на телефоне. Гонять скриншоты телефона
  через агента ради «посмотреть» — лишний круг.
- **Многое видно только на устройстве.** Так уже пойманы: безопасные зоны, молча
  неработающий экспорт, конкуренция акцентов, дефекты адаптивной иконки, наложение
  звука уведомления на звук приложения. Ни одно из этого в браузере не воспроизводится —
  не считать веб-API рабочими по аналогии. **И ещё больше ловит настоящая тренировка:**
  четыре бага третьей сессии нашлись за одну тренировку на площадке, включая тот,
  что жил с четвёртого шага и пережил два осмотра на телефоне.
- Цикл правки: `npm run check` → `npm run android:sync` → сборка → установка →
  список того, что проверить. Сборка требует явного `JAVA_HOME` — см. `docs/android.md`.
- Ни одного цвета, размера шрифта или скругления мимо токенов из `src/index.css`.
  Светлая тема вводится переопределением токенов, захардкоженное значение станет багом.
- Принятое архитектурное решение записывать в `docs/decisions.md` вместе с причиной
  и отвергнутыми вариантами. Не переспаривать уже записанные решения без нового аргумента.
- Реализовывать строго по порядку из `docs/progress.md`, не перескакивая вперёд.
- Экспортированные JSON с тренировками в репозиторий не коммитить — это личные данные.
- **В интерфейсе — «упражнение», в коде и данных — `Movement`.** Расхождение сознательное:
  `movementId` лежит в каждом подходе, и переименование поля переписало бы весь журнал
  ради косметики (см. [docs/decisions.md](docs/decisions.md) Д-17).

## Контекст пользователя

Занимается уличной калистеникой ~1 год: турник, брусья, отжимания. Тренируется на площадке
на улице, с телефоном в руке — отсюда требования: полный оффлайн, минимум тапов между
подходами, крупные тач-таргеты, никакого текстового ввода во время тренировки.
Телефон — Android. Тренировок в неделю — 3.
